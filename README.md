# proc-supervisor-kit

*In English.* A small kit for keeping long-running Node.js processes alive on a Windows machine without services or PM2: a Git Bash restart wrapper with exponential backoff (`run-forever.sh`), a heartbeat watchdog in TypeScript, and a safe deploy script template. The watchdog finds processes via CIM (with a fixed PowerShell script, no user strings spliced into it), kills a process whose heartbeat file went stale so the wrapper restarts it, starts what is missing, tails other logs, and deduplicates alerts within a time window. A PID lock plus exit code 3 keeps a second instance from starting, and the deploy script stops everything, backs up, scrubs secrets from old logs, checks syntax, does a dry run, starts and waits for a fresh heartbeat. TypeScript, Node ≥ 22.18 runs it directly, zero runtime dependencies.

---

Набор для долгоживущих Node-процессов на Windows-машине:

- **`run-forever.sh`** — обёртка перезапуска для Git Bash: упал — подняла снова, пауза растёт до предела; код выхода 3 — «не перезапускай».
- **Сторож** (`src/watchdog.ts`, команда `watch`) — следит за списком процессов из JSON-конфига: пульс, наличие, хвосты логов, алерты.
- **`deploy.sh`** — шаблон безопасного выпуска новой версии: остановить, проверить, что ноль, бэкап, вычистить логи, проверить, сухой прогон, запуск, ждать пульс.
- **Замок от второго экземпляра** (`src/lock.ts`) — файл с pid; второй экземпляр выходит с кодом 3.

Вынесено и переписано из моего долгоживущего сервиса на Node.js, который сутками работает на Windows-машине.

## Зачем

Процесс, который должен работать неделями на обычном Windows-компьютере, ломается тремя способами, и у каждого своё лекарство.

1. **Самовосстановление.** Процесс падает — его надо поднять, но не долбить перезапусками каждую секунду, если он падает сразу. Хуже, когда процесс не падает, а *зависает*: жив, но ничего не делает. Его видно только по пульсу — файлу, куда он раз в цикл пишет время. Пульс протух — сторож снимает процесс, обёртка поднимает его заново.
2. **Защита от дублей.** Два экземпляра одного процесса — это двойная работа и испорченное состояние. Обёртку могли запустить дважды, сторож мог не увидеть процесс и запустить второй. Поэтому процесс сам берёт замок и при живом владельце выходит с кодом 3, обёртка на код 3 не перезапускает, а сторож ничего не запускает, пока жива обёртка, и шумит, если видит два экземпляра.
3. **Безопасный выпуск.** Новую версию нельзя просто положить поверх: старые процессы надо снять все (сначала сторож и обёртки, иначе они поднимут процесс обратно), старую версию — сохранить, из старых логов — вычистить ключи до архива, новую — проверить до запуска, а после запуска — убедиться, что она реально работает, а не просто стартовала. И если что-то не так, сразу видеть, как откатиться.

## Быстрый старт

Нужны Node ≥ 22.18 (он запускает TypeScript сам, без сборки) и Git Bash для скриптов. Зависимостей во время работы нет.

```sh
git clone https://github.com/SHOTBOTik/proc-supervisor-kit
cd proc-supervisor-kit

# 1. пример процесса под обёрткой: пишет пульс в examples/worker.hb раз в 5 с
cd examples
bash ../run-forever.sh --log worker.log -- node worker.js &

# 2. сторож: один проход, ничего не трогая
node ../src/cli.ts watch watchdog.json --once --dry-run

# 3. сторож по-настоящему (обычно — тоже под обёрткой)
bash ../run-forever.sh --log watchdog.out -- node ../src/cli.ts watch watchdog.json

# 4. выпуск: сначала посмотреть план, потом выполнить
bash ../deploy.sh --config deploy.conf --dry-run
bash ../deploy.sh --config deploy.conf
```

Проверить, что сторож снимает зависший процесс: запустите пример с `WORKER_HANG_AFTER=3` — после трёх шагов он перестанет писать пульс, через `maxAgeSec` сторож его снимет, обёртка поднимет.

`npm install` нужен только для разработки: он ставит `typescript` и `@types/node` для `npm run typecheck`.

## run-forever.sh

```sh
run-forever.sh [--log FILE] [--name NAME] [--] command [args...]
```

- Строки `старт: …` и `стоп: код N после M с работы, перезапуск через K с` пишутся в `--log` (или в stdout), туда же — вывод команды.
- Пауза перед перезапуском: `RF_MIN_DELAY` (5 с), каждая следующая вдвое длиннее, но не больше `RF_MAX_DELAY` (300 с). Если команда проработала дольше `RF_RESET_AFTER` (60 с), пауза сбрасывается: редкие падения не копят задержку.
- Код выхода `RF_STOP_CODE` (3) — обёртка пишет `стоп` и выходит с кодом 0, не перезапуская.
- SIGINT/SIGTERM обёртке — она снимает команду и выходит.

## Сторож

```sh
node src/cli.ts watch <config.json> [--once] [--dry-run] [--verbose]
node src/cli.ts check <config.json>
```

Раз в `intervalSec` для каждого процесса из конфига:

1. Читает новые строки его лога (`tail`). Строки, совпавшие с `tail.alert`, становятся алертами. Усечение и ротация лога замечаются: файл стал короче, под тем же именем другой файл или изменились его первые байты — тогда чтение идёт с начала нового файла.
2. Ищет процесс: образ `image` (по умолчанию `node`) и командная строка, совпавшая с `match` и не совпавшая с `exclude`.
3. Решает:
   - процесс есть, пульс свежий — всё хорошо;
   - процессов больше одного — алерт о дубле;
   - пульс старше `heartbeat.maxAgeSec` — алерт и снятие; обёртка поднимет. Не снимает, если процесс моложе предела (ещё не успел написать первый пульс) или сторож сам снимал его недавно;
   - файла пульса нет, а процесс жив — алерт без снятия;
   - процесса нет, а обёртка (`wrapper`) жива — ждёт; если так `wrapperGraceTicks` тиков подряд — алерт;
   - нет ни процесса, ни обёртки — запускает `start` (отвязанно, без окна, без оболочки);
   - на машине есть `node` без видимой командной строки (процесс с другими правами) — второй не запускает, только пишет в лог.
4. Раз в `summaryEverySec` пишет сводку одной строкой: `сводка: worker ok, other down | тиков 360, алертов 3, подавлено 12, снято 1, запущено 0`.

**Алерты** идут в `alertsLog` и в stdout. Одинаковый алерт — не чаще раза в `dedupWindowSec` (по умолчанию 10 минут); «одинаковый» сравнивается без чисел, поэтому «нет пульса 12 мин» и «нет пульса 13 мин» — один алерт. Когда окно закрывается, приходит строка «… (повторилось N раз за 10 мин)».

**Свой лог** сторожа (`log`) ротируется по размеру: `logMaxBytes`, хранится `logKeep` старых файлов (`watchdog.log.1`, `.2`).

**Режимы:** `--once` — один проход и выход с кодом 0 (всё в порядке) или 1 (были алерты или действия) — удобно для проверки и для Планировщика задач. `--dry-run` — ничего не снимать, не запускать и не писать в файлы, только напечатать, что сделал бы. Без этих флагов сторож берёт свой замок рядом с конфигом: второй сторож с тем же конфигом выходит с кодом 3.

### Конфиг

Пути — от каталога конфига. Неизвестный ключ — ошибка: опечатка не должна молча выключать надзор. Полный пример — [`examples/watchdog.json`](examples/watchdog.json).

```json
{
  "intervalSec": 60,
  "log": "watchdog.log",
  "alertsLog": "alerts.log",
  "logMaxBytes": 10485760,
  "logKeep": 2,
  "dedupWindowSec": 600,
  "summaryEverySec": 21600,
  "wrapperGraceTicks": 2,
  "processes": [
    {
      "name": "worker",
      "match": "worker\\.js",
      "image": "node",
      "exclude": "--once|--dry-run",
      "wrapper": { "match": "run-forever\\.sh.*worker\\.js", "image": "bash" },
      "heartbeat": { "file": "worker.hb", "maxAgeSec": 120 },
      "start": { "command": "bash", "args": ["run-forever.sh", "--log", "worker.log", "--", "node", "worker.js"], "cwd": "." },
      "tail": { "file": "worker.log", "alert": "\\b(error|fatal)\\b" }
    }
  ]
}
```

| Ключ | Что это | По умолчанию |
|---|---|---|
| `name` | имя в логах и алертах | обязательно |
| `match` | регулярное выражение для командной строки; совпадающее с пустой строкой (`.*`) — ошибка | обязательно |
| `image` | имя образа: `node` совпадает и с `node.exe` | `node` |
| `exclude` | какие командные строки не считать | — |
| `wrapper` | обёртка: `match` и `image` | `image: bash` |
| `heartbeat` | файл пульса и `maxAgeSec` | — |
| `start` | `command`, `args`, `cwd` — если нет ни процесса, ни обёртки | — |
| `tail` | чей лог смотреть и `alert` — регулярка без учёта регистра | `\b(error\|fatal)\b` |

**Пульс** — файл, в котором лежит время: миллисекунды или секунды от эпохи, ISO-время; если там что-то другое — берётся время изменения файла. Писать лучше атомарно, через временный файл и переименование, — так делает `writeHeartbeat` из `src/heartbeat.ts`.

## Замок от второго экземпляра

```ts
import { lockOrExit } from './src/lock.ts';
lockOrExit('worker.lock', { match: /worker\.js/ }); // занят живым процессом — выход с кодом 3
```

Замок создаётся эксклюзивно (`wx`) и содержит pid. Если pid жив — второй экземпляр выходит с кодом 3. С `match` «жив» значит ещё и «его командная строка похожа на нашу»: Windows охотно выдаёт освободившиеся pid снова. Если процесс с этим pid не наш или мёртв — замок протух, его снимают и берут заново. При выходе замок снимается, если он всё ещё наш.

## deploy.sh

```sh
bash deploy.sh --config deploy.conf [--dry-run]
```

Конфиг — обычный bash, пример с комментариями — [`examples/deploy.conf`](examples/deploy.conf). Шаги:

1. **Остановить** процессы по `STOP_MATCH` — по порядку: сторож, обёртки, процессы. Потом пересчитать: если осталось больше нуля — стоп, до любых изменений.
2. **Бэкап** файлов `FILES` в `archive/<время UTC>/`.
3. **Логи** `LOGS` — вычистить секреты и переложить в `archive/<время>/logs/`. Встроенные правила: присваивания вида `token=…`/`"password": "…"`, заголовки `Bearer …`, пароль в URL, PEM-ключи, типовые форматы токенов. Плюс точные значения из `SCRUB_VALUES_FROM` (env-файлы; значения не печатаются, только число замен) и свои регулярки `SCRUB_PATTERNS`. Для строгой проверки архив можно прогнать ещё и сканером секретов, например [leak-guard](https://github.com/SHOTBOTik/leak-guard).
4. **Новая версия** из `SRC_DIR`, если задан.
5. **`node --check`** всех `ENTRIES`.
6. **Сухой прогон**: `DRY=1 $DRY_CMD`, должен выйти с кодом 0.
7. **Запуск** `START` отвязанно (или своя функция `start_app`, если процессов несколько).
8. **Пульс**: ждать до `HEARTBEAT_WAIT` секунд пульс новее момента запуска.

При неудаче на шагах 2–8 скрипт печатает, что сломалось, и готовые команды отката из только что сделанного бэкапа. Скрипт идемпотентен: повторный запуск снимает то, что работает, делает новый бэкап с новой меткой времени, пропускает отсутствующие логи. `--dry-run` только читает список процессов и печатает план.

Служебные команды, которыми пользуется `deploy.sh`, доступны и сами по себе:

```sh
node src/cli.ts ps   'worker\.js' [--image node] [--count]
node src/cli.ts kill 'worker\.js' [--image node] [--force] [--dry-run] [--max 10]
node src/cli.ts spawn --cwd app -- bash run-forever.sh -- node worker.js
node src/cli.ts beat worker.hb --max-age 60 --wait 30
node src/cli.ts scrub-logs --to archive/logs --values-from app.env -- app.log
```

## Как устроено

```
src/
  procs.ts      список процессов: CIM на Windows, ps на POSIX; поиск, снятие, отвязанный запуск
  watchdog.ts   decide() — чистое решение по списку процессов и пульсу; Watchdog — исполнение и сводка
  config.ts     проверка и разрешение конфига
  alerts.ts     окно дедупликации и счётчик повторов
  logfile.ts    лог с ротацией по размеру
  tail.ts       хвост чужого лога с учётом усечения и ротации
  heartbeat.ts  чтение и атомарная запись пульса
  lock.ts       замок от второго экземпляра
  scrub.ts      вычистка секретов из логов
  cli.ts        команды watch, check, ps, kill, spawn, beat, scrub-logs
run-forever.sh  обёртка перезапуска
deploy.sh       шаблон выпуска
examples/       worker.js, watchdog.json, deploy.conf
```

- **Процессы на Windows** — один постоянный PowerShell-скрипт через `-EncodedCommand`: `Get-CimInstance Win32_Process` → pid, родитель, имя, командная строка, время старта → JSON. Ни одна строка из конфига или аргументов в скрипт не попадает: фильтрация по регулярным выражениям идёт в JS. PowerShell 5.1 оставляет в командных строках сырые управляющие символы — они вычищаются до разбора JSON.
- **Не снять самого себя.** Поиск не считает свой pid и цепочку предков, а также оболочки с командой в строке (`bash -c "…"`, `cmd /c`, `powershell -Command`): в их командной строке искомое выражение — просто текст. Под Git Bash цепочка родителей Windows рвётся, поэтому одной проверки предков мало.
- **Решение отделено от действия.** `decide()` получает список процессов, возраст пульса и состояние и возвращает список действий. Тесты проверяют его на подменённых списках, ни один настоящий процесс не трогается.

## Ограничения

- Сделано и проверено для Windows + Git Bash. На Linux и macOS работает через `ps`, но там лучше systemd или launchd.
- Снятие на Windows — сразу `TerminateProcess`, без мягкой остановки: процесс должен переживать внезапную смерть (атомарная запись состояния, как у пульса).
- Процессы, запущенные от другого пользователя или с повышенными правами, видны без командной строки. Сторож тогда не запускает второй экземпляр, но и снять зависший не сможет.
- Обёртку, запущенную как `bash -c "…"`, сторож обёрткой не считает (см. выше) — запускайте её файлом: `bash run-forever.sh …`.
- Ротация «копировать и усечь», после которой файл успел вырасти и начинается с тех же байтов, не отличима от дозаписи.
- Вычистка логов — набор регулярок и точных значений, а не полноценный сканер секретов.
- Алерты — только в файл и stdout. Хотите в мессенджер — читайте `alerts.log` своим отправителем.
- Регулярки в `STOP_MATCH` и `match` делайте точными: `kill` снимет всё, что совпало, с любым образом, если не задан `--image`. Защита только от грубых ошибок: выражение, совпадающее с пустой строкой (`.*`, `x?`), отвергается, а если совпало больше `--max` процессов (по умолчанию 10), `kill` не снимает ничего.

## Тесты

```sh
npm install        # только typescript и @types/node
npm run typecheck  # tsc --noEmit
npm test           # node --test, без сети
```

Проверяются окно дедупликации и счётчик повторов, ротация лога, хвост с усечением и ротацией, протухание пульса, проверка конфига, решение сторожа на подменённых списках процессов, замок, вычистка логов, CLI на списках из файла (`--procs-from`), `bash -n` обоих скриптов, дымовые прогоны `run-forever.sh` с фейковым процессом (код 3, растущая пауза) и `deploy.sh --dry-run`. Если `bash` нет в PATH, тесты скриптов помечаются как пропущенные с причиной.
